# Integrated Lifecycle Proof

This record binds the source, package, clean-install, synthetic, and retained field assertions to one candidate. It is evidence for review, not a release or acceptance record.

## Exact Candidate

The tests bind the source tree under test to one `npm pack` archive and one clean
offline installation of that archive. Final acceptance must separately attest
the exact commit, tree, archive integrity, and installed-file manifest; this
document does not claim that such a final attestation has already been captured.

`test/files-lifecycle-reliability.test.js` exercises the source public-files lifecycle. `test/packed-package.test.js` packs once, installs that archive once in a clean target, and exercises the installed public handoff lifecycle. `test/integrated-proof.test.js` verifies packaged proof records and retained source-level negative-proof metadata.

For M4/M5, `test/packed-package.test.js` records the lifecycle binding rather
than accepting a caller label: the source CLI writes the packet and source
`init --adapter opencode` writes the source wrappers; the suite's local `npm
pack` archive is installed with `npm install --offline`; then the installed
`init --adapter opencode` writes the clean-install wrappers, command, and
reference that the installed measurement script reads. The retained pre-phase
M4/M5 observation is unavailable, so the test compares current source and
clean-install observations without inventing a reduction result.
